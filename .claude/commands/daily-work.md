# 每日工作流

请按照以下顺序完成日常工作检查，并在最后输出一份简洁的中文报告（总结今天的项目状态）。

## 1. 整理/检查本地文件

- 列出工作目录下的根目录文件，标注最近修改的文件（24 小时内）。
- 检查是否存在临时文件、未追踪的大文件、或者可能误提交的敏感文件（例如 `.env`、`*.key`、`credentials*`）。
- 如果发现需要关注的文件，把路径和原因写到报告里。**不要自动删除任何文件**。

## 2. 汇总项目进度

- 运行 `git log --since="24 hours ago" --pretty=format:"%h %an %s"` 查看最近 24 小时的提交。
- 运行 `git status` 查看当前工作区是否有未提交的更改。
- 运行 `git branch --show-current` 标记当前分支。
- 如果是 GitHub 仓库，使用 `mcp__github__list_pull_requests` 查看打开的 PR 数量与状态。
- 把这些信息整合成"今日提交 / 未完成更改 / 打开的 PR"三个小节。

## 3. 运行测试 / 构建

按下面顺序尝试，遇到第一个匹配的就执行，其他跳过：

1. 如果存在 `package.json` 且里面有 `"test"` 脚本：运行 `npm test`。
2. 如果存在 `pyproject.toml` 或 `pytest.ini`：运行 `pytest -q`。
3. 如果存在 `Cargo.toml`：运行 `cargo test`。
4. 如果存在 `Makefile` 且有 `test` 目标：运行 `make test`。
5. 都没有则跳过这一步并在报告中说明 "未检测到测试配置"。

如果测试命令失败，**不要尝试自动修复**，把失败的第一段错误信息（不超过 20 行）放进报告。

## 4. 输出报告

按以下格式输出，全部用中文：

```
📅 每日工作报告 — <今日日期>

📂 文件检查
  - <发现的事项，或"无异常">

📊 项目进度
  - 今日提交：<数量>
  - 未提交更改：<是/否，简述>
  - 打开的 PR：<数量与简述>

🧪 测试 / 构建
  - 状态：<通过 / 失败 / 跳过>
  - <若失败，附错误摘要>

✅ 建议下一步：<1-3 条简短建议>
```

报告输出完成后结束本轮任务，不要继续执行别的操作。
